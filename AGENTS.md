# AGENTS.md — контекст для AI-инструментов

Этот файл — точка входа для любого AI-агента, работающего с репозиторием (OpenAI Codex, Cursor, Copilot и др.). Claude Code дополнительно читает `CLAUDE.md`, Cursor — `.cursorrules`; при расхождениях этот файл и `CLAUDE.md` главнее (`.cursorrules` частично устарел — там Angular 18, фактически 20.3).

## Что за проект

**Agent Academy** — кликабельный прототип нового фронтенда B2B-платформы для российских страховых агентов. Заменяет устаревший UX веб-клиента 1С:Предприятие 8.3. Цель — показать собственникам, протестировать на 5–10 агентах, передать команде разработки.

**Это не MVP.** Реального бэкенда нет: все данные — моки через HttpInterceptor + Faker.js. Мок ≠ контракт: источник правды по API — `api-contract.yaml`.

**Аудитория (критично для каждого UX-решения):** реальный профиль — женщина ~48 лет из региона (Минусинск), старый ноутбук, нестабильный 3G, минимум 1366×768. Подробно — `USER_PROFILE.md`. Стиль — профессиональный российский B2B (Госуслуги, Сбербанк, Тинькофф Бизнес), **не** Linear/Vercel/Apple.

## Архитектурные правила (enforced ESLint, не обсуждаются)

- **Component → Service → ApiClient → HttpClient.** Компоненты не делают HTTP сами.
- **Standalone components** (никаких NgModules), lazy-loaded routes.
- **OnPush** change detection на всех компонентах.
- **inject()**, не constructor injection.
- **Signals** для UI-state, `toSignal` для async; RxJS только для HTTP и Reactive Forms.
- **Никаких `any`.**
- Формы — только Taiga UI через общий `<app-field>` (`tui-textfield`/`tuiInputDate`/`tuiSelect`), не сырые нативные `input/select`.
- UI-тексты по-русски, код и коммиты — английские идентификаторы.

## Залоченные решения (приняты владельцем — не переделывать без его слова)

- **h1 заголовки страниц — по центру** на всех экранах.
- **Шапка — navy брендовый** `#0C3363`; тёмный header не делать.
- **«Мои клиенты» — главная страница** (дашборда нет, удалён).
- **Таблица клиентов — 8 колонок:** Дата · Страхователь · Объект · № полиса · Продукт · Цена · Статус · СК. Новые колонки не добавлять — на 1366px таблица уже на пределе.
- **Имена — всегда полное ФИО с отчеством**, не обрезать многоточием.
- **Страница договора `/clients/:id`: процессы (изменения/расторжение/убыток) и кросс-продукты — ЗАМЕТНО**, не прятать. Это ключевое отличие от конкурентов и главная маржа.
- **1С — анти-референс UX:** копируем СЛОВА агента (терминологию из 1С), но не вёрстку/раскладку. Эталон — задача пользователя + наша дизайн-система.
- **Сигнал «Ждут ваших действий»** — в шапке; тёплый **янтарь**, не красный (красный только ошибки). Строки таблиц не красить.
- **Не прятать важные функции** в выпадающих меню.
- **Тёмной темы нет** и не предлагать по умолчанию.
- **КВ агента в рублях не показывать** на экранах котировок.
- **Логотипы не рисовать самим** — только готовые согласованные исходники (у владельца).
- Размеры под аудиторию: body 18px, кнопки ≥48px, контраст ≥4.5:1, десктоп-first 1366×768.
- Полный реестр — `/hub/doc/decisions` («Залоченные решения») в запущенном приложении.

## Регламент работы (важно!)

- **Прямой пуш в `main` запрещён.** Пуш в `main` автоматически деплоит прод на GitHub Pages (`.github/workflows/deploy.yml`). Работа — только в ветке `feat/<тема>` (или `fix/`, `docs/`) → Pull Request → ревью владельцем → merge.
- **Conventional Commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`), заголовок ≤100 символов. Husky-хуки (lint-staged + commitlint) не обходить `--no-verify` — если падает, чинить причину.
- **Атомарные коммиты**, одна страница/тема за итерацию, не «всё сразу».
- **Перед правкой — `git status`.** В репозитории параллельно работают несколько сессий/людей: чужие незакоммиченные файлы не трогать и не «подчищать». Спорную правку не продавливать — вопрос владельцу.
- Code-first: итерируем прямо в коде и браузере, без Figma-этапов.
- Перед PR: `ng build` и `ng lint` зелёные.

## Что НЕ делать

- Не предлагать middle-слой / NestJS / GraphQL — отложено явно.
- Не использовать NgModules, `any`, constructor injection.
- Не делать формы на сырых нативных полях — только Taiga UI.
- Не пытаться быть как Linear/Vercel/Apple в дизайне.
- Не предлагать тёмную тему, не делать тёмный header.
- Не скрывать важные функции в выпадающих меню.
- Не выдумывать данные/поля вне `api-contract.yaml` — «мок ≠ контракт».
- Не пушить в `main` и не релизить без явной команды владельца.
