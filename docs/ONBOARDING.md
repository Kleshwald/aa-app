# Онбординг: как подключиться к проекту

Инструкция для нового участника команды (продакт/дизайнер/аналитик), который дорабатывает прототип со своим AI-инструментом (OpenAI Codex, Cursor, Claude Code и др.).

## 1. Доступ к GitHub

1. Сообщите владельцу свой ник или почту на GitHub — он отправит приглашение в репозиторий `Kleshwald/aa-app`.
2. Примите инвайт (придёт на почту и появится в уведомлениях GitHub).
3. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/Kleshwald/aa-app.git
   cd aa-app
   ```

## 2. Два способа смотреть продукт

**Прод (ничего ставить не нужно):**
- Кабинет агента: https://kleshwald.github.io/aa-app/ — вход: любой номер телефона, пароль `6767`.
- Техпанель `/hub` (входы, документация, бэклог, залоченные решения): https://kleshwald.github.io/aa-app/hub — гейт `6767`.
- Имитация 1С 8.5 (отдельная полоса, самодостаточный HTML): https://kleshwald.github.io/aa-app/1c85.html и актуальная https://kleshwald.github.io/aa-app/1c85-v4.html.
- Доска обратной связи: https://kleshwald.github.io/aa-app/feedback.

**Локально:**
1. Node.js 20+ (https://nodejs.org).
2. `npm ci`
3. `npx ng serve --port 4200` → http://localhost:4200/login (любой логин/пароль).
4. Открывать в Edge или Chrome (Yandex Browser блокирует DevTools).

## 3. Как дать контекст своему AI

- **`AGENTS.md` в корне репо** — главная точка входа: проект, правила, залоченные решения, регламент. Codex и большинство инструментов подхватывают его автоматически; если нет — дайте прочитать первым же сообщением.
- Для Cursor есть `.cursorrules`, для Claude Code — `CLAUDE.md` (оба читаются автоматически своими инструментами).
- Порядок чтения документации для погружения человека: `README.md` → `CLAUDE.md` → `STATUS.md` → `USER_PROFILE.md` ⭐ → `PROJECT_BRIEF.md` → `/hub` в запущенном приложении.
- Бизнес-логика легаси-системы 1С (домен страхования: ОСАГО, процессы, статусы) — `docs/knowledge/`, начиная с `00-INDEX.md`.

Если работаете через **облачный Codex** (chatgpt.com/codex): после принятия инвайта подключите GitHub-аккаунт в Codex и выберите репозиторий `aa-app`; в настройках окружения укажите Node 20 и setup-команду `npm ci`. `AGENTS.md` Codex прочитает сам.

## 4. Регламент работы

1. **Никогда не пушить в `main` напрямую** — пуш в `main` автоматически деплоит прод на GitHub Pages.
2. Работа в ветке: `git checkout -b feat/<короткая-тема>`.
3. Атомарные коммиты в стиле Conventional Commits (`feat: …`, `fix: …`, `docs: …`), заголовок ≤100 символов. Хуки (lint-staged, commitlint) должны проходить — не обходить `--no-verify`.
4. Перед PR: `npx ng build` и `npx ng lint` зелёные.
5. Pull Request на `main` → ревью владельцем → merge (= релиз на прод).
6. `git status` перед началом: в репо параллельно работают другие сессии — чужие незакоммиченные файлы не трогать.

**Что согласовывать с владельцем ДО кода:** всё из раздела «Залоченные решения» в `AGENTS.md` (и полного реестра `/hub/doc/decisions`); новые страницы/разделы; изменения навигации; всё, что меняет смысл, а не полировку. Спорное — коротким вопросом с вариантами, а не готовым фактом.

## 5. Для владельца: выдача доступа (делается в веб-интерфейсе GitHub)

1. **Пригласить участника:** репозиторий → Settings → Collaborators → Add people → ник/почта → роль **Write**.
2. **Защитить `main` (рекомендуется):** Settings → Branches → Add branch ruleset / Add rule для `main` → включить «Require a pull request before merging». Без этого любой участник с Write может пушем в `main` молча зарелизить прод. Владельца-админа правило по умолчанию не ограничивает жёстко (можно разрешить bypass для админов).
3. Если участник работает через облачный Codex — с вашей стороны больше ничего не нужно: он сам подключит Codex к репо после инвайта.
