# Пролонгация — прототип v4

Спецификация локального HTML-прототипа по ТЗ от 21.09.2026. Стилистика существующего v4 сохраняется. Результаты локальной проверки приведены в конце документа.

Экран: `/1c85-v4.html#prolongation` при запуске локального сервера из `public`.

## Вкладки и фильтры

Визуальное уточнение: демонстрационный переключатель перенесён в «Ещё» → «Сценарий прототипа» («Показать без полисов» / «Показать полисы»). В пустом состоянии одиночная вкладка не рисуется: под заголовком страницы остаётся спокойная текстовая пометка, затем форма поиска НСИС. Это заменяет первоначальную большую кнопку над вкладками.

Уточнение 22.09: при отсутствии полисов в исходном списке пролонгации остаётся только вкладка «Поиск по базе НСИС» и сообщение «Полисы для пролонгации скоро появятся». Пустой результат фильтра не скрывает вкладки. В прототипе добавлен явно обозначенный переключатель «Нет полисов для пролонгации» / «Вернуть полисы» для проверки этого состояния; он не удаляет данные, сохраняет фильтры и не отключает поиск НСИС. В реальной системе состояние должно определяться наличием полисов агента, без демонстрационной кнопки.

- **ОСАГО**: аналитика, период окончания полиса, ответственный, тип клиентов, продукт, поиск и таблица.
- **Здоровье**: тот же набор элементов; основной список и аналитика содержат только годовые полисы.
- **Поиск по базе НСИС**: одноимённый блок, поля «ФИО страхователя», «Гос. номер», «Водительское удостоверение», кнопка «Найти», таблица результатов. Общих фильтров периода, ответственного и клиентов здесь нет.

Продукты ОСАГО: «Все продукты», «ОСАГО ФЛ», «ОСАГО ЮЛ».

Продукты здоровья: «Все продукты», «НС Спорт», «НС Универсальный», «Антиклещ».

При открытии обеих вкладок выбраны «Все продукты» и «Все клиенты».

Для ОСАГО сохраняются значения фильтра клиентов: «Все клиенты» (`all`), «Оформленные» (`issued`), «Одобренные» (`approved`), «Оформленные в РСА» (`rsa`), «Не прошли скоринг» (`declined`). Для здоровья используется тот же набор без пункта «Оформленные в РСА». Состояние клиента и цвет срока — разные признаки.

По итогам аудита 21.09.2026 владелец согласовал только удаление пункта РСА из здоровья. Формула уровня пролонгации ожидает уточнения; ФИО ответственного в таблицу, отдельный признак расчёта и изменения компоновки столбцов не добавляются.

Таблица и аналитика учитывают выбранные период, ответственного, продукт, тип клиентов и поисковый запрос. Настройки вкладок ОСАГО и здоровья независимы.

## Поиск здоровья и аналитика

Без поискового запроса месячные полисы скрыты. Поиск по клиенту или номеру полиса включает месячные договоры, но сохраняет остальные активные фильтры. Найденный месячный полис отображается в таблице и выгрузке с отметкой «Месячный».

По уточнению владельца поясняющие подписи о годовых/месячных полисах, подсказки о поиске и правом клике, формулы во всплывающих подсказках и фразы «вне аналитики» убраны из формы. До первого поиска НСИС показывает только заголовки таблицы. Названия полей, статусы, счётчик найденного, легенда цветов и сообщения об ошибках сохранены; логика поиска, аналитики и выгрузки не меняется.

Аналитика здоровья всегда рассчитывается только по годовым полисам текущей выборки, включая ограничение поисковым запросом.

**Допущение прототипа — требуется согласовать формулы с владельцем процесса:**

- «К продлению» — число подходящих полисов, которые ещё не оформлены на новый период.
- «Рассчитано» — число полисов с выполненным расчётом, включая уже оформленные.
- «Оформлено» — число оформленных продлений.
- «Уровень пролонгации» — оформленные продления / все подходящие полисы выборки × 100%; при пустой выборке — 0%.

Это демонстрационная трактовка, а не окончательное бизнес-правило. При фильтре «Оформленные» уровень по выбранной группе может составить 100%.

## Цветовая индикация

Для воспроизводимости используется фиксированная дата демонстрации **21.09.2026**. Описание цветов расположено внизу формы.

- Зелёный — полис продлён; это состояние имеет приоритет над датой окончания старого полиса.
- Жёлтый — непродлённый полис заканчивается сегодня или через 1–10 дней включительно.
- Красный — непродлённый полис уже просрочен.
- Для остальных полисов — обычное отображение без сигнала срочности.

## НСИС и выгрузка

НСИС работает на демонстрационных данных, без подключения к реальному API. Заполненные поисковые поля объединяются условием **И**. После нормализации хотя бы одно поле должно содержать поисковое значение; одни пробелы или удаляемые разделители не запускают поиск.

**Допущение прототипа — требуется уточнить при интеграции:** достаточность одного поля, обязательный состав идентификаторов и правила нормализации должны быть сверены с реальным контрактом НСИС. Эти условия не объявляются окончательными правилами сервиса.

В таблицах пролонгации по правому клику доступна команда **«Вывести список…»**. В HTML-прототипе она сохраняет текущие строки в CSV с UTF-8 BOM, разделителем `;` и экранированием значений для Excel. Учитываются все активные фильтры и поисковый запрос; найденные месячные полисы здоровья входят в выгрузку.

## Приёмочные проверки

1. Открыть экран напрямую по указанному адресу; проверить три вкладки и начальные значения фильтров.
2. На ОСАГО совместно изменить период, ответственного, продукт и тип клиентов; сравнить таблицу с аналитикой.
3. Проверить включение обеих границ периода, пустую выборку и обратный диапазон дат.
4. На здоровье убедиться, что месячные полисы скрыты без поиска; найти месячный по клиенту и по номеру, сохранив активные фильтры.
5. Убедиться, что месячный результат не входит ни в один показатель аналитики, но присутствует в выгрузке.
6. Сверить показатели с формулами выше, включая оформленный рассчитанный полис и пустую выборку.
7. Проверить цвет для просроченного полиса, окончания сегодня, через 10 и через 11 дней; продлённый старый полис должен оставаться зелёным.
8. Переключить ОСАГО → здоровье → ОСАГО и проверить независимость значений продуктов и фильтров.
9. На НСИС проверить пустой запрос, нормализуемые значения, поиск по одному полю, сочетание полей и отсутствие совпадений.
10. Правым кликом выгрузить отфильтрованную таблицу; сверить число и содержимое строк, читаемость кириллицы и разделителей.
11. Проверить читаемость формы на 1366×768, доступность нижней легенды и отсутствие наложения элементов.

## Результат локальной проверки · 21.09.2026

- Синтаксис встроенного JavaScript и 36 проверок логики прошли: начальные значения, совместные фильтры, границы периода, месячные полисы и показатели, CSV, цвета сроков, поиск НСИС и экранирование текста.
- В браузере проверены три вкладки, годовой список здоровья, поиск месячного, комбинация фильтров ОСАГО, пустая выборка, сброс, некорректный период и НСИС. Ошибок JavaScript в журнале нет.
- Команда «Вывести список…» скачала CSV; проверен сам файл — BOM, кириллица и ровно одна отфильтрованная строка месячного полиса.
- На 1366×768 поля не перекрываются; широкая таблица доступна через горизонтальную прокрутку, легенда расположена под ней.
- `npm run lint` и `git diff --check` прошли. Полную Angular-сборку подтвердить не удалось: процесс завершился с кодом 134 на Node 25 и на Node 24, включая запуск с одним worker. Причина не установлена; сообщение об успешной сборке отсутствует. HTML-прототип проверен отдельно и не требует Angular-сборки для локального просмотра.
- В общую ветку и на GitHub Pages изменения не опубликованы.
