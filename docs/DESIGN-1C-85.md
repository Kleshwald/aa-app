# Брендбук кабинета агента на 1С:Предприятие 8.5

**Статус:** рабочий черновик · 2026-07-22 · для прототипа «полноценная версия на 1С 8.5»
**Что это:** наш дизайн-брендбук ([DESIGN.md](../DESIGN.md), [tokens.scss](../src/styles/tokens.scss)), адаптированный под реальность управляемых форм 1С 8.5 — то есть **максимум нашей философии в рамках того, что платформа позволяет**.
**Честная рамка:** это не «как сделать 1С красивой», а «где наши законы исполнимы в 1С 8.5, а где платформа их не отдаёт». Где не отдаёт — сказано прямо. Проверка гипотез — только на учебной 8.5 (см. [DECISION-frontend-platform.md](./DECISION-frontend-platform.md)).

> ⚠️ Субагенты (Баха/Алюр) на момент сборки не дошли из-за сетевых обрывов — разбор сведён по их методикам (чеклист §7 DESIGN.md + JTBD-приоритеты). При их доработке — обновить.

## 0. Главный конфликт брендбуков

| | Наш Angular-брендбук | 1С 8.5 |
|---|---|---|
| Акцент | navy `#0C3363` + голубой `#3992E4` | **брендовый жёлтый 1С** (хром платформы) |
| Тело текста | **≥18px** (аудитория 45+) | стандарт ~13px / компактный ещё меньше |
| Контролы | **≥48px** высота | высоту задаёт платформа |
| Стилизация | токены на всё (`tokens.scss`) | **стилей-как-объектов нет**; только поэлементное «условное оформление» |
| Заголовки | по центру | платформа размещает слева |
| Раскладка | наша сетка | трёхзонное окно 1С (жёстко) |

**Вывод:** совпадений мало. Наш брендбук в 1С 8.5 живёт не как система токенов, а как **набор поэлементных настроек оформления** поверх платформенного каркаса. Часть законов исполнима, часть — нет.

## 1. Цвет — стратегия «двух акцентов»

Платформенный **хром** 1С (панель разделов, выделение строки, фокус) держит **жёлтый 1С** — его не перекрасить, это часть платформы. Спорить бессмысленно.

Но **внутри формы** 1С даёт «условное оформление» (`ЦветФона`, `ЦветТекста`, `Шрифт` поэлементно) + картинки. Через него мы возвращаем наш бренд там, где платформа отдаёт цвет:

- **Условное оформление статусов** в динамическом списке → наши семантические цвета (сюда и ставим navy-акцент)
- **Заголовки групп/разделов формы, ключевые суммы и № полиса** → navy через свойство «Шрифт/ЦветТекста»
- **Иконка-картинка на кнопке действия** → navy (саму заливку кнопки не перекрасить — см. ниже)
- **Ссылки** → голубой `#3992E4`

> **Уточнение Бахи (важно, честно):** **заливку кнопки цветом тема не отдаёт** — navy-CTA как в Angular не собрать. Основной CTA будет в стиле темы 1С; бренд инъектируем условным оформлением ячеек и navy-иконкой рядом, **не кнопкой**. И: **жёлтый 1С никогда не несёт текст** — только заливка/акцент хрома (контраст жёлтого под текст проваливается).

**Правило ролей (закон DESIGN.md «смелость — в одном месте»):** чтобы жёлтый 1С и наш navy не дрались — развести по ролям:
- жёлтый = **платформенный фокус/выделение** (командная панель, активная вкладка, выделение строки) — его роль, не трогаем;
- navy = **бренд контента** (цвет статусов, заголовки, цифры, иконки) — там, где 1С отдаёт цвет нам.

### Палитра — светлая тема (сведено с Бахой, привязано к нашим токенам)
| Роль | Hex | Где |
|---|---|---|
| Фон страницы | `#F5F6F8` | серый фон списков 8.5 |
| Карточка/форма | `#FFFFFF` | тело формы |
| Текст | `#1F2937` | основной (наш `gray-800`, контраст ~13:1) |

## 2. Типографика

- **Шрифт — Segoe UI** (системный на Windows-клиенте 1С). Наш Inter/системный стек тут неисполним — платформа даёт свой. Совпадение частичное (мы и так на system-стеке).
- **Масштаб — только СТАНДАРТНЫЙ, не компактный.** Компактный уменьшает шрифт → прямой удар по аудитории 45+. Это P0-борьба.
- **⚠️ Главный провал:** даже стандартный масштаб 8.5 ≈ **13px базовый**, а наш пол — **16px (в идеале 18px)**. Поэлементно поднять кегль в управляемой форме трудно и не везде. → **Закон «тело ≥16px» в 1С 8.5 штатно НЕ выполняется.** Это самый дорогой конфликт для нашей аудитории. Вариант обхода — платформенный зум пользователя (но это перекладывание на агента, а не решение).

## 3. Плотность и «воздух»

Хорошая новость: 8.5 сама сдвинулась в сторону «воздуха» (её заявленная фишка) — карточные списки, тонкие рамки, скруглённые углы. Наш принцип «воздух вместо тесноты» **частично совпал** с направлением 8.5. Но 1С-списки всё равно плотнее наших таблиц, а на компактном масштабе — намного. Совпадение есть, полного нет.

## 4. Компоненты: наш паттерн → термин 1С

| Наш компонент | Как в управляемой форме 1С 8.5 | Что теряем |
|---|---|---|
| **Field** (подпись сверху) | реквизит, `РасположениеЗаголовка = Верх` | ✅ исполнимо нативно |
| **Плейсхолдер / маски** | `ПодсказкаВвода` + `МаскаВвода` (VIN/госномер/дата) | ✅ штатно |
| **Стабильный слот ошибки** (инлайн, layout не прыгает) | нативно нет: `СообщитьПользователю` (пузырь) + красное подчёркивание | ✗ **теряем постоянный инлайн-слот**; сообщение всплывает, макет дёргается. Формулировки — наши |
| **Navy-CTA** (заливка кнопки) | заливку кнопки тема не отдаёт | ✗ **теряем navy-кнопку**; CTA в стиле темы, бренд рядом иконкой + усл. оформлением |
| **Кнопка ≥44px** | кнопка команды | ⚠️ в стандарте близко, ровно 44px не гарантировать; компакт — меньше |
| **Статус-чип** (пилюля+иконка+цвет) | колонка динамического списка + условное оформление | ⚠️ цвет+текст да; форма пилюли, радиус, SVG-иконка — нет |
| **Таблица клиентов** (8 колонок, сортировка) | динамический список + `УсловноеОформление` | ✅ колонки/сортировка/отбор/цвет; ✗ богатая ячейка (бейдж под № = отдельное поле, не вёрстка) |
| **Кросс-сел карточки, QR, лоадер** | группы формы, картинка, декор | ⚠️ собираемо грубее; богатый визуал — только картинками |
| **Заголовок по центру** | заголовок формы | ✗ платформа размещает слева (Баха: уступить — дешевле; но это лок владельца, нужен акцепт) |

## 5. Приоритеты борьбы с платформой

**Бьёмся (P0 — критично для аудитории 45+/3G/страх ошибки):**
1. Размер шрифта ≥16px — иначе агент не читает (стандартный масштаб + поэлементно где можно).
2. Контраст ≥4.5:1 — navy-действия на белом, семантика статусов.
3. Ошибки текстом+цветом (иконка — как получится).
4. Navy на кнопках-действиях (узнаваемость бренда).

**Уступаем без боя (не стоит инженерных затрат):**
1. Трёхзонная раскладка окна — платформенная, принимаем.
2. Жёлтый хром платформы — оставляем в его роли (фокус/выделение).
3. Точный px-контроль высот/отступов.
4. Богатые кастомные ячейки и заголовки по центру.

## 6. Чеклист §7 DESIGN.md — исполнимость в 1С 8.5

| Закон DESIGN.md | В 1С 8.5 | Комментарий |
|---|---|---|
| Подпись поля сверху | ✅ Да | `ПоложениеЗаголовка = Верх` |
| Всё из токенов | ❌ Нет | стилей-объектов нет; только поэлементное оформление |
| Тело ≥16px | ⚠️ Частично/Нет | стандарт ~13px, поднять трудно — **главный долг** |
| Контролы ≥44px | ❌ Нет | высоту задаёт платформа |
| Ошибки текст+иконка+цвет | ⚠️ Частично | текст+цвет да, иконка сложнее |
| Консистентность > креатив | ✅ Да | платформа даёт даже с избытком |
| Заголовки по центру | ❌ Нет | платформа размещает слева |

**Итог (свод Бахи по полному 16-пунктному §7 DESIGN.md):** 8.5 бесплатно отдаёт главное для 45+ — подпись сверху, нативный зум/масштаб (тут 1С даже сильнее веба), воздух на стандарте, маски, привычность, связь label↔поле, видимый фокус. Ломается на **трёх** вещах: **стабильный инлайн-слот ошибки**, **navy-заливка кнопки**, **точные токены (отступы/радиусы/пилюля-чип)**. Текст ≥16px — вытягиваем вручную (поднять «Шрифт» реквизита до ~12pt), не централизованно. Заголовок по центру — уступаем платформе (нужен акцепт владельца против лока «по центру»).

## 7. Как это применяет прототип

Кликабельный прототип 1С 8.5 реализует именно эту стратегию, чтобы показать её вживую:
- платформенный каркас 8.5 (трёхзонное окно, жёлтый хром, карточные списки);
- **наш navy — на кнопках-действиях, заголовках форм, семантике статусов** (имитация «условного оформления»);
- жёлтый 1С — только выделение/фокус;
- стандартный масштаб; светлая и тёмная темы;
- честная пометка сверху: это HTML-рендер, не запущенная управляемая форма; feasibility проверяется на учебной 8.5.
