# 01. Обзор системы (легаси)

> Источники: `01_func_characteristics.txt`, `03_tech_architecture.txt`, `10_skolkovo_report.txt`, `PROJECT_BRIEF.md`.
> Легенда меток — см. [00-INDEX](./00-INDEX.md).

## 1. Что это

**[Ф]** «Agent Academy» — интернет-сервис (SaaS), выполняющий функцию **страхового и финансового агрегатора** для страховых агентов и предпринимателей, работающий по модели **B2B** `[ист: 03_tech_architecture.txt, 10_skolkovo_report.txt]`. Правообладатель — **ООО «Агент Академи»** (ИНН 7727473161, ОГРН 1217700441727, Москва) `[ист: 01_func_characteristics.txt]`.

**[Ф]** Реализовано на **1С:Предприятие 8.3** + MS SQL Server, размещено в ЦОД в РФ (152-ФЗ). Доступ через веб-браузер, адрес `b2b.agentacademy.ru` `[ист: 03_tech_architecture.txt, PROJECT_BRIEF.md]`. Детали as-is — в [11-legacy-architecture](./11-legacy-architecture.md).

**[Ф]** Сегмент рынка сознательно узкий: **удалённые районы Сибири и Дальнего Востока** `[ист: 08_module_osago.txt — термин «Сегмент»]`. Это объясняет и профиль пользователя (старый ноут, 3G), и всю логику «открытости территории».

## 2. Назначение и цели

**[Ф]** Заявленные цели сервиса `[ист: 01_func_characteristics.txt]`:
- Оптимизация и ускорение оформления/управления полисами для агентов и страховщиков.
- Сокращение ручной обработки заявок и анализа риска (автоматизация).
- **Скоринг страхователей**, сегментация продаж, управление настройками продуктов, **контроль убыточности портфеля** в разрезе СК.
- Управление страховыми операциями: пролонгация, внесение изменений, расторжение, **урегулирование убытков**.
- Отслеживание статуса операций и страховых случаев.
- Сбор поведенческих данных для бизнес-анализа и прогнозирования (ML/NLP — заявлено).

## 3. Акторы и роли

**[Ф]** Классы пользователей `[ист: 08_module_osago.txt §3.1, 10_skolkovo_report.txt §2.3]`:

| Роль | Кто это | Что делает |
|------|---------|-----------|
| **Агент** | Профессионал, представляет интересы СК, продаёт полисы | Оформление, пролонгация, ведение клиентов, получение КВ. **Главный пользователь нового фронта.** |
| **Субагент** | Работает под агентом по договору | Привлечение клиентов, оформление; без прямых полномочий от СК |
| **Куратор** | Управляет агентами и субагентами | Координация, обучение, поддержка, мониторинг результатов; связь агент↔СК |
| **Администратор** | Управляет платформой | Доступы (RBAC), настройки продуктов/сегментации/профилей, чёрные списки, данные клиентов |
| **Ответственный пользователь** (сотрудник СК) | Обрабатывает пул | **Дооформление** полисов, оформленных через «Автопомощник» (см. [06](./06-autoassistant.md)) |
| **Техподдержка 1-й линии** | Внутренняя роль | Обработка заявок (изменение/расторжение/убыток), чат с агентом (см. [10](./10-processes.md)) |

**[Ф]** **Один номер телефона = один личный кабинет** `[ист: 03_tech_architecture.txt §7.3]`. В прототипе логин = номер телефона (см. `CLAUDE.md`), а не ИКП/email.

**Внешние акторы (не пользователи, но участники процессов):** страховые компании-партнёры, РСА/НСИС, поставщики данных (DaData, ApiCloud, SpectrumData), эквайеры (Best2Pay, ЮКасса), почтовый сервис (Dashamail). Детали — [11](./11-legacy-architecture.md).

## 4. Функциональные модули (легаси)

**[Ф]** `[ист: 01_func_characteristics.txt, 03_tech_architecture.txt §3.2]`:

| Модуль | Назначение |
|--------|-----------|
| Управление пользователями | Регистрация, 2FA, роли/права (RBAC), OTP, восстановление пароля |
| **Оформление полисов** | ОСАГО (ФЛ/ЮЛ), ипотечное, страхование жизни/здоровья, КАСКО/Мини-КАСКО, кросс-продукты. Пролонгация, изменения, расторжение |
| **Финансовый (КВ)** | Начисление и управление комиссионным вознаграждением агентов/партнёров; выплаты; контроль убыточности портфеля |
| Аналитика | Отчёты (базовый, по пролонгации, по пулу, «мой отчёт»); графики; выгрузка Excel/текст |
| Клиентская база («Мои клиенты») | Учёт клиентов, котировки, история; поиск/фильтры |
| **Скоринг / Сегментация** | Алгоритмическая оценка соответствия клиента требованиям СК; чёрные списки; ML/NLP; интеграция SpectrumData/ApiCloud |

**[Ф]** Продукты, которые оформляются `[ист: 01_func_characteristics.txt UI, PROJECT_BRIEF.md]`: ОСАГО, Ипотека, КАСКО/Мини-КАСКО, продукты «Здоровья» (НС универсальный, НС спорт, Антиклещ), дополнительные (кросс-) продукты — Юрист поможет, НС при ДТП, Надёжная поездка, МиниКАСКО.

## 5. Ключевые цифры

**[Ф]** `[ист: PROJECT_BRIEF.md]`:
- Сейчас: **1500 пользователей**, **300 активных/день**.
- Цель: рост до **10 000 пользователей**, **2000 активных/день**.
- 7 страховых компаний-партнёров (список и расхождение с прототипом — см. §6).
- Затраты на лицензии 1С: ~250 тыс. ₽/мес на 50 лицензий (одна из причин ухода от веб-клиента 1С).

**[Ф]** Целевая доступность системы **99.5%** `[ист: 03_tech_architecture.txt §8]`; бэкапы ежедневно, глубина 30 дней.

## 6. Границы и важные оговорки

**[Ф] Список СК расходится между источниками:**
- Тех.архитектура называет партнёрами 7 СК: **Ренессанс, Югория, Зетта, СОГАЗ, Росгосстрах, Согласие, Евроинс** `[ист: 03_tech_architecture.txt §6.1]`.
- Раздел интеграций детализирует API для: Ренессанс, Югория, **Евроинс, Ингосстрах**, Согласие, Зетта `[ист: 10_skolkovo_report.txt]` — здесь **Ингосстрах**, но нет детальных методов СОГАЗ/Росгосстрах.
- Прототип (`insurance-companies.fixture.ts`) содержит 8 СК: Ренессанс, Югория, Согласие, Зетта, РГС, СОГАЗ, Евроинс, **Энергогарант** — **нет Ингосстраха**.

→ **[П]** Актуальный список СК на V1 нужно подтвердить у владельца (см. [13, Q6](./13-open-questions.md)). Для домена важно: **у каждой СК своя схема интеграции** — это не «7 одинаковых адаптеров».

**[Ф]** Заявлены ML/NLP и «персонализированный подход» `[ист: 03_tech_architecture.txt §1.2, 10_skolkovo_report.txt]`, но в документах это на уровне деклараций (скоринг + сегментация). Конкретные ML-модели/фичи не описаны — см. [08](./08-segmentation.md). Архитектура V1 ML-инфраструктуру явно исключает (`ARCHITECTURE.md`).

**Что в новом прототипе НЕ повторяем:** трёхуровневую 1С-архитектуру, веб/тонкий/толстый клиенты 1С, раскладку экранов 1С. Наследуем **терминологию агента** и **бизнес-правила**.
